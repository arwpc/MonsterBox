    Sir Dragomir (character 4) → 100%

    Prepared 2026-09-19, straight after PumpkinHead was finished and locked. Everything below was measured on his own node (192.168.8.130), not inferred from this repo — his data files are node-local and the repo's copies are a shadow.

    Where he stands right now

    Area State Verdict
    Code 10.5.1 (fleet is on 10.6.0) behind — deploy first
    Service /health OK, HTTPS on 3000 good
    Camera mjpg-streamer serving, 116 KB snapshot at 640×480 good (his unit needs 640×480 — 320×240 yields zero frames)
    Speaker ReSpeaker XVF3800 sink, vol 0.55, default needs an ear-check
    Microphone part 5 is "Webcam Microphone"; the XVF3800 array is what's on the bus suspect — see STT below

    Magic Box servo (part 3, ch 11) calibrated by hand, 16–178°, inverted good

    Jaw animation config enabled, part 2, minAngle 0 / maxAngle 180 contradicts the measured 27–74 window

    Poses 4 thin — needs a real set
    Scenes 0 the big gap

    The punch list, in order

    1. Bring him to 10.6.0 — bash scripts/deploy-to-animatronic.sh 4 192.168.8.130, then prove it: /health version + /fleet-verify. His parts, poses, super-powers, movement config, calibration, scenes, gestures and queues are all excluded from the rsync, so the deploy brings code only.
    2. Fix STT. Ten consecutive failures today is the loudest thing in his logs. Prove the capture layer and the voice gate separately: capture through the app's own path (python_wrappers/microphone_cli.py) and judge on FRAMES (non-zero bytes AND non-zero RMS), never on "the device opened". His stt-config.json points at part 5 with microphoneDeviceId: "default" while the XVF3800 array is the device present — check that first.
    3. Ear-check the speaker. success: true proves nothing; record and transcribe. Not during quiet hours.
    4. Re-type and re-calibrate the head servo (part 1). Its own description says it is the CONTINUOUS-rotation goBILDA Stingray-2 variant with no position feedback, but its calibration profile is an autoGenerated absolute-servo 0–900 placeholder. Those two cannot both be true, and the placeholder is what head tracking would drive. A full rotation tears the head cabling — short, operator-supervised spins only, never an automated sweep.
    5. Fix the jaw animation window. The active jaw config says 0–180 while the measured servo window is 27–74. Set it through POST /setup/jaw-animation/api/jaw-animation/4 (it lands on the ACTIVE config and refreshes the cache; a hand edit of super-powers.json is masked until restart).
    6. Tune audioLeadTimeMs by ear (currently 750). The jaw leads the audio by physics; positive delays the jaw. Cold and warm differ — tune per node.
    7. Decide the eyes. He has no led_ring. If he gets one, it is an Add Part
    8. /setup/led-animation job and unlocks ledSync speech-reactive eyes.
    9. Build the pose library (4 today). Idle/neutral, a look-left/right pair from the head servo's real travel, jaw open/closed, magic-box open/closed.
    10. Build scenes (0 today). This is what "100%" mostly means for him — PumpkinHead's bar was a character that reliably runs what the operator wants, end to end.
    11. Voice check. TTS is eleven_v3, voice wXvR48IpOq9HACltTmt7 ("Ancient Monster", renamed Dante — that is correct, do not "fix" it), stability 0.5 / similarity 0.8 / speed 0.9. Confirm by ear before calling it done.
    12. Lock him when the operator says 100%: node scripts/character-lock.mjs lock 4 --reason "..." --by "...", then commit and deploy so the lock travels. Pull his authoritative config into the repo FIRST, the way PumpkinHead's was, so the fingerprints record what he actually runs.

    Standing cautions for this node

    • Part 1 is the 900° multi-turn neck: full rotation tears head cabling. Agents drive it only on operator direction; automated suites must not command it.
    • His camera needs MB_CAM_RES=640x480; the fleet-wide 320×240 gives him zero frames while every status field still reads healthy.
    • Judge cameras by FRAMES, audio by ear-check, and capture by RMS. Every success: true on this stack can lie.
