    v11 — Project Plan & Session Handoff

    Written: 2026-08-20 Repo state at handoff: d0dd60b5, pushed, working tree clean apart from node-local config/app-config.json and an untracked ARCHIVE/. Version in package.json: still 10.4.0. Bump to 11.0.0 only at the release tag.

    0. The one-paragraph brief

    Aaron has three live animatronics — Mina (2), Orlok (3), Sir Dragomir (4) — and wants them to reliably perform a show. He is explicitly tired of chasing individual faults and wants a stable, verified v11 rather than more improvements. Ship a small release you can trust; defer anything that does not stop a show. His words: "I want this codebase rock solid and stable and every part of it working before I make any other changes."

    Do not expand scope. If you find something new, write it down and finish the plan.

    2. Hard safety constraints — read before commanding anything

    These are not style preferences. Each one is backed by a real incident.

    1. NEVER command Orlok parts 3, 4, or 5.
    2. 3 Bow At The Waist — blockAllMotion; parts.json and the part description contradict each other on the BTS7960 wiring, so "extend" may physically retract.
    3. 4 Elbow — blockAllMotion; electrically dead; shares a fused rail.

    4. 5 Forearm Rotation — travel never measured; deliberately guarded to a narrow 95–125° window centred on its resting position. Do not widen, do not sweep. The rail has blown a fuse.

    5. NEVER command Sir Dragomir part 1 (neck) until it is calibrated with eyes on it. goBILDA Stingray-2, 900° multi-turn. A full rotation tears the head cabling.

    6. A servoType: "continuous" part turns an ANGLE command into a timed SPIN. hardwareService/index.js rewrites it to rotate_continuous_pca <ch> <dir> <speed> 1000 and discards the requested position. Always check config.servoType before sending an angle. This is how the knight's neck accumulated 99 spin commands.

    7. Do not relabel Orlok part 15 as multi-turn. See §4.3 — it is the mirror-image trap.

    8. PumpkinHead (1), Groundbreaker (5) and Renfield (6) are in storage. Offline is expected and is never a finding. Do not ping, deploy to, test, or report them as failures.

    4. What this session changed, and why

    All 16 commits are on origin/main. Full messages carry the reasoning; summary:

    4.1 Fixed faults

    • Playback truncated every line over 15 seconds. Three call sites in serverPlaybackService.js used a flat 15000 ms watchdog, so a 16.3 s line was SIGTERMed mid-sentence and returned playback_timeout. Now _playbackTimeoutMs(buffer, contentType) scales to payload duration, 15 s floor, 300 s ceiling.
    • Sir Dragomir's neck was mislabelled continuous. See §2.3. Corrected to multi-turn + rotationRangeDeg: 900. Config only — no motion was ever commanded. His calibration profile is deliberately left kind: continuous-servo and uncalibrated, so the drive path still refuses him. Re-kinding it decides which adapter runs and belongs in the supervised session.
    • Jaw sync slider capped at ±500 ms while the engine already clamped to ±1000. Widened.
    • Orlok's jaw was binary open/closed. sensitivity: 2.8 saturated the perceptual mapping — 57% fully-open, 34% shut, 7% in between, only 14 of 19 quantisation levels reachable. Measured on his own voice; sensitivity: 1.0 gives 8/34/56% and all 19 levels. Also smoothing 0.4→0.65, releaseTime 108→150. Applied at runtime via the API, not committed — super-powers.json is node-local.
    • Two fleet-audio tools reported healthy nodes as dead because they shelled out to bare ssh and only worked from a node with outbound key trust. New scripts/fleet-audio/ssh-auth.mjs.
    • The release gate was generating SSH keys. tests/unit/system-admin-guard.test.js probes the guard via /api/system/ssh/keys/generate; five cases pass the guard and reach the real handler, so every npm run gate wrote 5 keypairs to ~/.ssh. Found at 760 keys / 3.1 MB. Now cleaned up per-run; the strays were swept.
    • A suite could leave the fleet permanently silent. Mute persists to data/speaker-state.json and reapplies at boot. The test now snapshots and restores the operator's real value.
    • Deploy shipped one node's telemetry to every other node — startup-health.json, performance-history.json, scene-analytics.json, manual-nodes.json were gitignored as node-local but missing from the rsync excludes.

    4.2 Documentation corrected

    • Sir Dragomir's head servo channel was recorded three different ways: ch0 in docs, ch1 in the repo, ch4 on the node. ch4 is truth. Jaw is ch0, not ch1. (Historical — superseded 2026-08-22: the operator physically moved the jaw to ch1; verdict procedure in BENCH-CHECKLIST K1. The head remains ch4.)
    • His "Continuous Servo Gotchas" section said the neck must never be used for head tracking or poses. With position control it can be both.
    • OPERATOR-TODO.md gained the USB over-current finding.

    4.3 A deliberate non-change worth understanding

    Orlok part 15 is named "Head on a Swivel", and the Stingray-2 model note says "Used for 'Head on a Swivel' and similar applications". Aaron used a goBILDA in the first build and cannot easily see what is in there now. It was left alone, because his calibration is the proof: a Stingray swept across 500–2500 µs travels ~830° (2.3 rotations); he measured a clean 3–169° window and has a working head. Relabelling it multi-turn would remap 0–180 onto 0–1800 and silently break a working calibration. Same class of uncertainty as the knight, opposite correct action — there a wrong label was actively causing harm; here the label is harmless and changing it would cause harm.

    5. Known findings not yet fixed

    5.1 Dashboard — audit complete, 23 verified findings

    Root causes, not 23 separate bugs:

    1. Nothing refreshes. Chips read once at page load and never poll: jaw public/js/dashboard.js:641, mute :833, lurk :464, motion :1509, audio device lists :2229. refreshBadges() polls every 1.5 s but only mirrors the checkbox into the badge — it never asks the server, so a stale checkbox is reflected forever. refreshPageState() at :679 already calls every server-truth loader and is never invoked on a timer. That is the fix.
    2. Failures are swallowed. saveJawSettings() at :1535 discards the POST response entirely; the server returns 200 {"success":false,"error":"Jaw servo has no calibrated Min/Max window"} and the switch stays lit. This is Aaron's "it doesn't deploy to the dashboard when I enable jaw animation". Same shape at :321 (Lurk latches Head and Idle ON after both failed) and :730 (mute ignores its own response).
    3. The audio info he asked for is not rendered. views/conversation/showtime.ejs:98 — no microphone shown at all. :134 — no output level. dashboard.js:1264 — the speaker selector shows a part name, never the device it resolves to.
    4. Capability is not applied to the chips. dashboard.js:450 — per-node capability reaches only the command-bar badges, so Mina offers a head-tracking toggle she structurally cannot do (capabilities.headTracking === false).

    His feature request, verbatim: a dropdown on the dashboard to select current input and output on the live animatronic, saved behind the scenes so it is not lost when you leave the page.

    Useful existing pieces: showToast(message, type) at dashboard.js:1341; loaders loadJawSettings (:1525), loadHeadTrackStatus (:1389), loadLurkCapabilities (:436).

    5.2 Head tracking must support two servo kinds AND two camera mounts

    These are independent axes. Dispatch servo kind on profile.capability.kind (already read into servoKind at headAnimationSuperPowerService.js:153 and then thrown away — nothing branches on it). Camera mount must become a head-tracking setting, cameraMount: 'head' | 'fixed'.

    Orlok Sir Dragomir
    Pan servo absolute 3–169° multi-turn 900°, ch4
    Camera in his eye, moves with the head fixed to the body
    Loop closed — vision sees the result; this is why his offset setting exists open — no feedback on head position

    The current gate is purely angle-based (bounds → parts.json markers → placeholder), so a servo with bounds: null can never satisfy it. That is why the knight logs "no usable calibrated window — refusing to drive it".

    5.3 Poses

    • 9 of Orlok's 35 poses command the dead Elbow (part 4), including "Neutral Standing", the idle/home pose. Only the safety quarantine stops them — [poseLibrary] Idle pose "Neutral Standing" (1) excluded — Elbow is quarantined. If the safety teardown ever happens, wipe these first, or nine poses immediately start driving a dead servo on a fuse-blown rail.
    • poses.schema.json validates nothing: parts: {"type": "array"} with no item schema. That is how poses referencing forbidden parts got written. Worth tightening — it is author-time data validation, not a runtime nanny, so it does not conflict with the deferred teardown.
    • The pose engine already supports continuous/velocity targets: poseEngine.js:185 reads target.continuous: { direction, durationMs, speedPct }. Angle targets use target.angleDeg.

    5.4 Hardware — operator only, tracked in docs/hardware/OPERATOR-TODO.md

    • Orlok ch4/ch5 need dedicated 10 A circuits.
    • Dead servo channels: Mina ch8 Neck, ch11/12 Eye; Orlok part 2 Left Arm.
    • Mina's USB 5 V rail trips over-current — 24 events, camera re-enumerated 3× (1-1.4, dev 5→6→7), everything behind two cascaded hubs. This may be faking the "dead" Unitek capture input at 1-1.2 rather than the adapter being broken. Try a powered hub before replacing anything. It also threatens calibration accuracy: a part measured through a sagging rail may not measure the same twice.

    Two findings from that agent ARE real and verified, and are worth keeping:

    1. A hardware test can report success while doing nothing. services/hardwareService/exec.js returns status: 'success' with simulated: true when it falls back to simulation, and logs the reason with console.warn — which lands only in /var/log/monsterbox.err. A .log-only read looks clean. Any re-run of the probe must reject simulated: true and score aliveness on driver reach or observed motion, never on a success field. Same family as muted playback returning played: true.
    2. Orlok part 14 "Sensor for Orlok" is a data bug, not a calibration job. parts.json types it motion_sensor, but it carries an absolute-servo profile with a hand-set (autoGenerated: false) 12–180 window. A motion sensor has no angle window. Calibrating it moves nothing. Fix the data; do not send anyone to a rig for it.

    Requirements for the re-run: drive each candidate via POST /api/parts/:id/test on the node that OWNS the part, passing characterId explicitly (part ids are only unique within a character); reject simulated: true; exclude 192.168.8.150 and .200 rather than letting them zero out the run; and keep every safety rule in §2, especially the exclusions for Orlok 3/4/5 and Dragomir part 1.

    9. Working practices that earned their place

    • Audio is proven by ear-check, never by an API success field. generate-and-play returns {"success":true,"played":true} while muted — a nine-line conversation across three nodes reported success on every call and made no sound. Confirm muted:false first, or record and measure.
    • Read BOTH logs. console.warn/console.error go only to /var/log/monsterbox.err. The refusal reason is there while .log still reads healthy.
    • Establish the boot boundary before reading a log tail. /var/log/monsterbox.err has no timestamps of its own. This session raised a false alarm about a servo being spun by comparing against a timestamp-less tail; the spins were historical.
    • Node-local files lie across nodes. parts.json, calibration_profiles.json, super-powers.json, app-config.json are all excluded from deploy and drift independently. Orlok was found holding a stale copy of the knight's part definition.
    • /health version and git HEAD both lie about deployed code. rsync excludes .git, so peer nodes show HEAD at 609245f5 (v9.3.0) with ~150 dirty files while running current code. Grep the node for the actual symbol.
    • Other Claude sessions drive the same fleet. Six were live during this session and one muted all three nodes mid-task. If a setting reverts, suspect a peer session before suspecting the code — ListAgents shows them.
    • Never stage a service-written data file while a suite is driving that service. This session committed jawAnimation.enabled: false — a test's transient state — and had to correct it.
    • The deploy password is at /etc/monsterbox/env as MONSTERBOX_SSH_PASSWORD. Read it; do not ask.
