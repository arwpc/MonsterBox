    STATE YOU INHERIT

    HEAD = the latest commit on main, pushed to GitHub. Version in package.json = 10.1.0 (SHIPPED). Gate passes. Fleet: Mina 192.168.8.140 (char 2, LOCAL), Orlok 192.168.8.120 (char 3), Sir Dragomir 192.168.8.130 (char 4) — all serving 10.1.0 and all VERIFIED muted. PumpkinHead (1) and Groundbreaker (5) are deliberately unplugged; Renfield (6) has no address.

    *** AUDIO POLICY ***

    The household was woken at 00:20 by two animatronics talking. Speaker audio stays OFF unless the operator says otherwise IN YOUR SESSION. Moving hardware IS allowed — the operator confirmed: "Moving hardware is silent - just no loud audio." Recording from a mic is fine and often required. Verify before starting: curl -sk https://localhost:3000/conversation/api/speaker-mute → muted:true.

    Mute now survives restarts (data/speaker-state.json). A node WITHOUT that fix comes back audible — seed the file before restarting any node that lacks it.

    WHAT LANDED (do NOT redo)

    Committed & pushed, gate green: - Calibrated stamp — isCalibrated() in server/calibration/store.js, POST /api/calibration/:partId/calibrated, toggle on the Bounds panel. Works for ALL capability kinds (only absolute-servo has bounds; continuous-servo / openloop-linear are bounds:null). Refuses only a zero-span window. Stamp OFF is reversible. - Speaker mute persists across restarts, including npm run deploy:all. Proven on all 3 nodes. - Panic hardened — POST /api/panic now ALSO kills every media/hardware child process (mpg123/ffmpeg/pw-play/aplay/vlc + python_wrappers/*.py) and disables AI, persisting that. Enumerates PIDs and signals individually; never pkill -f (it matches its own shell and this repo's path). The app itself is explicitly excluded. Verified: live process killed, /health still 200. - Audio-tag filter — stripAudioTags() / textForModel() in services/elevenLabsTTSService.js. Tags are stripped ONLY for models that would pronounce them; v3 keeps them, because there they ARE the performance. The operator may want those bracket sounds — do not make this always-on. - conversationalMode per character in tts-config.json, surfaced on the AI voice settings page: greys out what the agent overrides, deep-links to https://elevenlabs.io/app/agents/<agent_id>. - Models registry path FIXED — getModelDefaultsForPart() was resolving data/character-N/<file>, which never existed. See "current" below. - docs/hardware/OPERATOR-TODO.md — the hands-on list.

    ElevenLabs (all six agents, each write verified by re-reading the response): optimize_streaming_latency 3→0 on all six · # Names correction block on all six · audio tags reconciled · ignore_default_personality = true on all six · interactivity rewrite on all six (prompt char counts and KB counts verified before/after on every one).

    CORRECTIONS TO INHERITED BELIEFS — do not repeat these errors

    1. optimize_streaming_latency: 3 does NOT disable the text normalizer. Level 4 does. (0=off, 1=normal, 2=strong, 3=max latency opts, 4=max + normalizer off.) Verified against current ElevenLabs docs. The real normalizer control is the separate text_normalisation_type, which is INCONSISTENT across the fleet: Orlok elevenlabs, Mina + Dragomir system_prompt. Never reconciled.
    2. Local tts-config.json CANNOT reach a conversation, and it is enforced at the agent, not by our code: every agent has overrides.conversation_config_override.tts.* = false. Stop looking for a code path that "forgets" to send them.
    3. A node's /health version is NOT proof of a deploy. deploy-all.sh rsyncs files without moving git. Two nodes served 10.0.1 while running pre-af2c1037 code; Dragomir's git HEAD read v9.3.0 with 107 dirty files. Grep the node for the actual fix. The operator: "they're almost always behind the commit" — deploy BEFORE testing.
    4. Sir Dragomir's neck is NOT a software problem. ch1 emits perfect PWM (1645 µs CW / 1348 µs CCW, correct duration, clean release, no creep) and is SILENT (+0.4 dB) while ch0 on the same chip gives +29 dB. It is electrically/mechanically dead. Earlier sessions blamed the channel (already correct) and then the modelId fix (which was still broken anyway). Do not re-diagnose it in software.
    5. minPulse/maxPulse/neutralPulse are DEAD DATA. grep across servo_cli.py, pca9685_control.py, servo_daemon.py, hardwareService/index.js = zero hits. Pulse mapping is hardcoded (standard 500–2400; continuous 1000/1500/2000). Confirmed by measurement: jaw at 131° gave 1880 µs = 500 + 131/180*1900. Decide: wire them through, or delete them from data/models/servo_models.json. They have sent two investigations after the wrong cause.

    CURRENT DRAW — settled, do not reintroduce software caps

    Operator, verbatim: "the power supply is 30 amp and 800 W and all of the big parts are driven directly 12v. Everything else is a teeny dedicated servo - think rc cars that run concurrently all day long on the same hardware. No current issue." And: "Current is only an issue with that stupid elbow and forearm, and it's because I have them wired using the same power and they max out and blow a fuse. They each need dedicated 10a circuits, which I'll add if you put it in my list."

    Both software speed caps were removed for this reason. blockAllMotion, noRetractBelowMin, the angle window, the duration cap and power-group serialization all REMAIN. Orlok parts 4 (Elbow) and 5 (Forearm Rotation) stay blocked until his dedicated 10 A circuits exist — never command ch4/ch5 on Orlok.

    THE WORK, IN PRIORITY ORDER

    1. PCA9685 CHANNEL MAP — the operator's live question, highest value

    He has CONFIRMED the servos are physically attached and the board has external 5 V supplied continuously just for servos. An I2C scan found exactly one PCA9685 at 0x40 on every node — no second board. He suspects the channel assignments in parts.json are wrong: "I think Mina has his servos on zero, four, nine, 11, but I may be wrong."

    That fits the evidence: parts.json says Jaw ch4 / Neck ch8 / Eye ch11, and measurement found ch4 MOVES (+14 dB), ch8 and ch11 SILENT despite correct changing PWM. If the Neck is really on ch9, an off-by-one looks exactly like a dead servo.

    DO: sweep channels 0–15 on Mina and Orlok, small moves only, and produce a measured map. - Witness trap: both nodes carry a Unitek Y-247A whose capture side is DEAD (flat −79.7 dBFS), and on Mina ALSA default routes to it — recording from default scores every channel silent. Use the camera-mic card by number (≈ −50 dBFS). Validate with a positive control AND an idle control before trusting any silence. - Ground truth: python_wrappers/i2c_servo_sampler.py samples the PCA9685 LEDn registers. - Mina ch0 carries a LIGHT (3 V relay on a servo channel) — it will not sound like a servo. - Orlok: skip ch4/ch5 entirely (fuse policy above). His recorder has a ~6.6 dB startup artifact at t≈1.3 s and ~1.6 s clock offset — measure with an idle run first. - Report the remap; apply to parts.json only after the operator confirms.

    A PCA9685 cannot report what is attached — one-way I2C→PWM, servos have no back-channel. Empirical sweeping is the ONLY way. Do not look for a software enumeration.

Logs are SPLIT — grep BOTH: console.log → /var/log/monsterbox.log; console.warn/error → only /var/log/monsterbox.err. They are binary-ish: use grep -a.

    7. SAFETY BUGS FOUND BY THE HARDWARE PASS — none fixed

    • 🔴 nudge starts from a fabricated 90°. AbsoluteServoAdapter.js:12 hardcodes this.currentAngle = 90, and getOrCreateAdapter() in router.js passes the stored position only to OpenLoopLinearAdapter. Observed live: Dragomir's jaw was at 131.5°; a {"dir":"min","scale":"fine"} nudge reported "Nudged min at fine" and drove it to 88° — a 43.5° jump, below its calibrated minimum of 97°, because nudge is intentionally bounds-free. The smallest, safest-looking control is the one that hits the mechanical stop. Seed the adapter from the position store; refuse dir/scale nudge when position is unknown.
    • 🟠 A "nudge by −0.05" landing on p=0 silently becomes a ~2.75 s full-force endstop drive (OpenLoopLinearAdapter ENDPOINT_OVERDRIVE_FACTOR = 0.50). Correct for homing, dangerous for a 5% move.
    • 🟠 durationMs is silently discarded for open-loop parts (gotoNormalized reads only opts.timeoutMs).
    • 🟠 Inverted parts report the angle asked for, not driven: Mina part 2 has invert:true; commanded 60°, register went to 119.6°, API replied "Moved to 60°".

    8. OTHER OPEN ITEMS

    • USB signature stored on the MODEL — the operator's idea, refined by him: match at the manufacturer/model level, NOT the individual unit.

      "Don't make it unique to one device, just a manufacturer or something so I know I'm using the same WebCam or whatever part." So store idVendor:idProduct (e.g. 046d:0825) plus the product/manufacturer strings on the entry in data/models/webcam_models.json / microphone_models.json / speaker_models.json — do NOT store the per-unit serial. VID:PID identifies the model; the serial identifies one physical unit, and using it would make an identical replacement webcam read as "wrong device", which is the opposite of what he wants. Read it from lsusb / /sys/bus/usb/devices/*/{idVendor,idProduct,product,manufacturer}. Value: the part page can then say "this IS the model you configured" or "this is a DIFFERENT model than the one on record", which closes the deviceIndex / deviceId / resolution / fps silent no-ops (a webcam that moved /dev/video* currently fails invisibly), and it directly helps the two dead Unitek Y-247A capture inputs — MonsterBox could name the device it is about to open instead of trusting an index. USB only. Impossible for servos — a PCA9685 is a one-way I2C→PWM driver and a servo has no back-channel, so channel identity can only ever be established by driving it and observing (item 1).

    • Sir Dragomir has ZERO scenes and defaultSceneId: null, so he silently drops out of every fleet queue loop and the fleet call still reports success.
    • PumpkinHead's prompt still self-contradicts: "You never use audio tags" vs its own # Audio Tags section. Tags were cleared to []; the stray section remains.
    • Mina's text_normalisation_type differs from Orlok's — reconcile or explain.
    • Orlok's ASR keywords already contained every household name and did NOT prevent the Anya/Marniak drift — find out whether keywords affect agent OUTPUT or only guest transcription.

    ORCHESTRATION — the lesson that cost two sessions

    Subagents HANG. Tonight two Agent-tool subagents went silent with 130-byte transcripts — one had barely started, the other had finished its edits and died before returning. Their file edits survived on disk and were salvaged by inspecting git status, not by waiting.

    • Workflows journaled reliably; bare Agent calls were the ones that hung. Prefer Workflow.
    • ONE narrow question per agent, SMALL schema, explicit tool-call budget, and "return partial results rather than digging on."
    • Poll transcript byte-growth every ~3 min. No growth for 4 minutes → kill and re-shape. Do not wait 15.
    • Do mechanical greps/edits INLINE — your own tool results are checkpointed permanently.
    • Never tell an agent to "ignore a system reminder" — a safety classifier blocks the run. State the verified fact instead ("the connector is authorized; the lead has made many successful calls this session") and let it try. One agent was lost to this exact phrasing.
    • Two agents refused ElevenLabs work citing a stale "MCP needs authorization" notice. It is wrong — the connector works; it was used successfully dozens of times tonight.
    • Never run two prompt-writing agents against the same ElevenLabs agent concurrently.

    Gotchas

    • pkill -f <pattern> matches your own shell AND this repo's path. List PIDs with ps, kill by PID.
    • SSH lands in /home/remote, NOT the repo. Absolute paths always.
    • bc and pactl are not installed (use wpctl/pw-dump, XDG_RUNTIME_DIR=/run/user/1000).
    • microphone_cli.py stream_raw <device> <rate> <channels> — 3rd arg is CHANNELS, not duration.
    • An API {"success":true} proves a write landed, NOT that sound played or a part moved.
    • SSH: sudo sh -c '. /etc/monsterbox/env; export SSHPASS="$MONSTERBOX_SSH_PASSWORD"; sshpass -e ssh remote@<ip> "<cmd>"'
