# MonsterBox hardware

## Never command these — each rule is backed by a real incident

1. **Orlok (3) parts 3, 4, 5.** Bow (3): `blockAllMotion`, wiring docs contradict — "extend"
   may physically retract. Elbow (4): electrically dead, shares a fuse-blowing rail.
   Forearm (5): travel never measured, guarded to 95–125°; the rail has blown a fuse.
   There is **no software current or speed cap anymore** — the only protection is not
   commanding them. Dedicated 10 A circuits are on Aaron's list; until then, hands off ch4/ch5.
2. **Sir Dragomir (4) part 1 (neck)** until calibrated with eyes on it. goBILDA Stingray-2,
   900° multi-turn — a full rotation **tears the head cabling**. Its calibration profile is
   deliberately left `kind: continuous-servo` and uncalibrated so the drive path refuses it.
3. **Do not relabel Orlok part 15 ("Head on a Swivel") as multi-turn.** Probably also a
   Stingray, but Aaron's measured 3–169° window works; remapping 0–180→0–1800 silently breaks
   a working head. Mirror-image of the knight: there the wrong label caused harm, here
   changing it would.
4. **Don't retract Orlok's bow actuator below its min** (operator directive).

## Servo-kind traps

- `config.servoType: "continuous"` turns an ANGLE command into a **timed spin**
  (`rotate_continuous_pca <ch> <dir> <speed> 1000`) and discards the position. Check the
  kind before sending any angle — this accumulated 99 spins on the knight's neck.
- `minPulse`/`maxPulse`/`neutralPulse` in `servo_models.json` are **dead data** — pulse
  mapping is hardcoded (standard 500–2400 µs, continuous 1000/1500/2000). Measured: 131°
  → 1880 µs. Don't chase them.
- Inverted parts historically reported the angle *asked for*, not *driven* — verify with the
  register sampler when it matters.

## Calibration data

- Read bounds via `calibratedBounds(profile)` / `store.get()` — never raw `profile.bounds`.
  `autoGenerated: true` spans are placeholders the read path deliberately withholds.
  **A pose may only use a part with a real measured window.**
- Trusted windows live in `docs/development/V11-HANDOFF.md` §3, read from each node's own
  files (node-local — see `monsterbox-fleet`).
- Every `controlPart()`/calibration-store call must pass `characterId` — part ids are only
  unique within a character; omitting it has driven the wrong PCA9685 channel.
- `nudge` now seeds from the position store and **refuses when position is unknown** — that
  refusal replaced a 43° jump into an endstop. Don't weaken it.

## Proving a part is alive

- **A PCA9685 cannot report what is attached** — one-way I²C→PWM, servos have no
  back-channel. Driving and observing is the only method. USB devices are the opposite:
  identify them by `idVendor:idProduct` (model-level, never per-unit serial).
- `services/hardwareService/exec.js` returns `status:'success'` with **`simulated: true`**
  on fallback, logging the reason only to `/var/log/monsterbox.err`. **Reject
  `simulated:true`**; score aliveness on driver reach or observed motion, never a success field.
- Acoustic witnesses trap: a dead capture device or ALSA `default` routed to one scores
  everything silent. Run a **positive control and an idle control** before any silence means
  anything. Per-channel measured map for Mina: `docs/hardware/PCA9685-CHANNEL-MAP-MINA.md`.
- ReSpeaker XVF3800: `arecord`/`parec`/`ffmpeg` open it and deliver zero frames — PyAudio via
  `python_wrappers/microphone_cli.py` is the only proven capture path. Judge on FRAMES
  (non-zero bytes AND RMS). Traps: `docs/hardware/RESPEAKER-XVF3800.md`.
