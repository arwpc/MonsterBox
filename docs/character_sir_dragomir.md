## Head Servo — multi-turn, NOT continuous rotation

The Head Servo (**ch4**) is a **goBILDA Stingray-2 gearbox: 900 deg (2.5 turns) of MULTI-TURN
POSITION travel**. It was long recorded here as a continuous-rotation servo, and `parts.json`
carried `servoType: "continuous"` to match. That was wrong, and it was dangerous:

- `hardwareService/index.js` routes a `continuous` servo's ANGLE command to
  `rotate_continuous_pca <ch> <dir> <speed> 1000` — it SPINS for a second instead of moving to a
  position. The log shows 99 such commands historically.
- A full rotation **tears the head cabling**.

Corrected to `servoType: "multi-turn"` (2026-08-20), which routes to the multi-turn positioning
path instead. Consequences:

- It **holds position** and is commanded by angle, like any positional servo.
- Its **calibrated window is the cable guard** — not a timing guess. Keep travel inside it.
- It **can** be used for head tracking and in poses, as an angle target.
- Its travel is 0-900 deg, not 0-180, so never assume the 180 default for this part.

**The scale bug is FIXED in software (v10.4.0, 2026-08-22).** The part declares
`rotationRangeDeg: 900` and the whole path now speaks REAL degrees: the calibration page
shows a 0–900 control, goto/nudge/bounds are real degrees, and the conversion to
`move_to_pca_multi`'s fixed 0–1800 scale happens once in `hardwareService` (real 450° →
wrapper arg 900; unit-tested). This is what made the head "occasionally rotate all the way
around": most small commands landed under the deadband and did nothing, while any large one
commanded hundreds of real degrees in a single hop.

Still to do: **BENCH-CHECKLIST K3** — a supervised calibration to establish the cable-safe
min/max in real degrees, with eyes on the part and slack in the loom.

**What actually refuses it until then (verified in code):** only the paths that require a
measured calibration window — poses, scenes, head tracking — refuse this part, because its
profile is an `autoGenerated` placeholder that `calibratedBounds()` withholds. **Direct API
commands are NOT refused**: the calibration nudge/goto endpoints and `POST /api/parts/1/test`
go through `controlPart()`, where every per-part limit was removed by the 2026-08-20 operator
ruling — a command there WILL drive the head. It is also listed in `config/physical-faults.json`
(char 4, part 1) so automated suites and diagnostics never pick it, but that file is advisory:
nothing in the request path reads it. The lockout is procedural — only K3 commands part 1.

**Default/center pose:** Jaw 90°, Magic Box 90° (the head has no safe center until calibrated).
