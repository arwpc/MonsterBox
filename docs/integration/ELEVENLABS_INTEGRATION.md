# ElevenLabs Integration

## Overview

MonsterBox uses **ElevenLabs** as its sole AI voice provider, replacing the legacy three-API system (OpenAI Whisper STT + ChatGPT + TopMediai TTS) with a unified ElevenLabs solution.

## Architecture

```
User Input → ElevenLabs Conversational AI → Audio Output
           ↓
    Real-time WebSocket Connection (port 8795)
           ↓
    Integrated STT + AI Agent + TTS
```

### Services
| Service | File | Purpose |
|---------|------|---------|
| TTS | `services/elevenLabsTTSService.js` | Voice synthesis via REST API |
| STT (batch) | `services/elevenLabsSTTService.js` | File-based transcription |
| STT (realtime) | `services/elevenLabsRealtimeSTTService.js` | WebSocket streaming STT |
| WebSocket | `services/elevenLabsWebSocketService.js` | Conversation bridge (port 8795) |
| Config | `services/aiConfigStore.js` | Per-character AI config management |
| Playback | `services/serverPlaybackService.js` | Audio playback on character speakers |
| Server Mic | `services/serverSTTListener.js` | PipeWire microphone input for STT |

## Models

| Service | Model ID | Description |
|---------|----------|-------------|
| TTS | `eleven_v3` | Default — most expressive, supports audio tags |
| TTS | `eleven_flash_v2_5` | Low-latency alternative (~75ms) |
| TTS | `eleven_multilingual_v2` | High-quality narration |
| STT | `scribe_v2` | Batch transcription, 90+ languages, keyterm prompting |
| STT | `scribe_v2_realtime` | WebSocket streaming, ~150ms latency, VAD |

## Per-Character Configuration

Each character can have its own TTS and STT settings:

```
data/character-{N}/ai-config/
├── tts-config.json    # voice_id, model, stability, similarity
└── stt-config.json    # model, language, sample rate, VAD
```

Loaded via `aiConfigStore.getTTSConfigForCharacter(characterId)` with fallback to global `data/ai-config/tts-config.json`.

## Speech Pipeline

All speech paths use direct service calls:

```javascript
// Generate TTS audio buffer
const { buffer } = await elevenLabsTTSService.generateSpeech(text, ttsConfig);

// Play on character's assigned speaker
await serverPlaybackService.playAIOnCharacterSpeaker(buffer, characterId);

// Drive jaw animation (parallel)
jawAnimationService.driveFromBuffer(buffer, characterId);
```

This applies to:
- `/api/say` (make character speak)
- `/api/ask-ai` (AI conversation → TTS response)
- Scene `sayThis` steps
- Scene `askAI` steps (via `elevenLabsWebSocketService.askAgentQuestion()`)

### Jaw range (v9.0.0)
Jaw motion is clamped to the part's **real** calibrated window on every speech path. The
calibration store stamps uncalibrated absolute-servos with a full-span 0–180 placeholder
marked `autoGenerated`; that placeholder no longer outranks hand-set Min/Max markers in
`parts.json`, and is used only as a last resort where no markers exist. This visibly reduces
jaw travel on characters whose markers are narrower than 0–180 — that is the correct behavior,
not a regression.

> **Tuning note:** on the agent path, jaw opening is proportional to audio RMS scaled by the
> character's jaw `sensitivity`. Agent audio is quieter than TTS output, so a sensitivity
> tuned for TTS can leave the agent path opening only part way. Adjust on
> `/setup/jaw-animation` with the jaw physically watched.

## Conversation Flow

### WebSocket Conversation (port 8795)
1. Browser connects to `ws://host:8795`
2. Server streams microphone audio via PipeWire — **one continuous capture process** for the
   life of the session (`serverSTTListener.startContinuousCapture()`), re-framed into steady
   250 ms frames for downstream consumers
3. Audio sent to Scribe v2 Realtime for streaming STT
4. Transcribed text sent to ElevenLabs Agent
5. Agent response streamed back as TTS audio
6. Audio played on character speaker with jaw animation, driven **per 50 ms frame** of the
   incoming PCM rather than once per network chunk

### Continuous microphone capture (v9.0.0)
Capture used to spawn a fresh recorder per tick (~500 ms of audio for ~1450 ms of wall clock),
so roughly two thirds of what was said never reached the agent. One long-lived process now
streams headerless PCM16LE @ 16 kHz mono, with candidates tried in order:

| Order | Command | Notes |
|-------|---------|-------|
| 1 | `parec` | needs explicit `--latency-msec=50 --process-time-msec=20`, else its default buffering adds ~2 s |
| 2 | `ffmpeg` | `-f pulse` input, `-f s16le` to stdout |
| 3 | `arecord` | `-D pulse`, `PULSE_SOURCE` set from the resolved device |

A stream that produced audio and then died retries the same method; one that never produced
any advances to the next candidate, with exponential backoff capped at 8 s. All three commands
ship with the standard install (`pulseaudio-utils`, `ffmpeg`, `alsa-utils`) — no new dependency.

> ⚠️ **Changing a character's microphone requires restarting the conversation session.** The
> stream binds one device when the session starts. Toggle the agent/conversation off and on
> after changing the device.

`serverSTTListener.captureChunkWav()` is unchanged and still used by batch/one-shot callers
(including `microphone.record` in the hardware service).

### Fallback (batch STT)
If Realtime STT is unavailable, falls back to batch Scribe v2 polling. **Headless sessions
(the agent started from the conversation toggle rather than a browser) skip this branch** —
the agent does its own ASR and there is no client to receive transcripts.

## Troubleshooting

### Common Issues
1. **API Key Not Working** — Verify format `xi_...`, check account credits
2. **Voice Not Playing** — Check PipeWire routing: `wpctl status`, `pactl list short sinks`
3. **STT Silent** — Verify microphone: `pactl list short sources`, check character mic assignment
4. **WebSocket Connection Failed** — Check port 8795 availability, check logs

### Debug Commands
```bash
journalctl -u monsterbox -f
curl http://localhost:3000/ai-management/api/status
curl http://localhost:3000/api/elevenlabs/stt/capabilities
```
